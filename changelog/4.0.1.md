# Time.Tracking.Jira 4.0.1

Rewrite of the main interface in **WPF** with a new design. The application is still .NET
Framework 4.8 in a single executable: WPF was added to the existing project instead of
creating a new one, so the Jira layer, persistence, and v3 dialogs are reused untouched.

Scope: 35 files — 24 new, 3 removed.

---

## Interface

### Four views over the same time engine

Chosen in Settings and **switched live**, without restarting:

| View | What it's for |
|---|---|
| **Ledger** | Table, one row per subtask. This is the default view. |
| **Cards** | Wide cards, each action with its name written out. |
| **Focus** | One timer on stage, the rest as a queue. |
| **Grid** | Cells in two columns, keyboard-oriented (chips 1–9). |

The classic window (`MainForm`) is still available as a fifth option. Switching to it, or
from it, **does require a restart**: it's the boundary between two different message loops.
Between the four WPF views, the switch is instant.

`GridTimeTrackerForm`, the WinForms grid from v3 (1926 lines), is removed. The Ledger view
is its direct successor: same columns, same density.

### Adding and editing directly from the grid (Ledger)

- **Double-clicking the last row** creates a task right there, without going through the
  dialog.
- The *Parent* and *Subtask* columns turn into **combo boxes** on double-click, as in v3.
  Parents come from the issues assigned to the user; subtasks are queried from Jira once the
  parent is chosen. Both accept free text.
- `Enter` jumps from the parent to the subtask; `Escape` closes the editor.
- **Double-clicking the time** edits it, reusing v3's dialog and its validation.

The *Add issue* dialog still exists. These are two paths to the same thing, not a
replacement.

### Window sizes

- Each view opens at a size fitted to its content and has its own minimum, measured by
  shrinking it until it starts clipping.
- **The size is remembered between sessions**, one per view.

## Behavior

### The timer starts without an issue

You no longer need to pick an issue to start counting. The issue is only required **when
logging the time to Jira**, which is where it's actually needed. This covers the common
case of realizing you're working before knowing what to bill it against.

Only applies in Ledger, the only view where a row can be created without an issue.

### Other

- Global shortcuts in every view: `1`–`9` start a row, `Space` pauses, `R` resets,
  `Ctrl+↑` logs to Jira, `Ctrl+N` adds.
- Empty rows that are abandoned are no longer saved, so they don't reappear on every
  startup.
- *Log all* (Grid view) now skips rows without an issue instead of chaining a warning for
  each one.

## Fixes

**Worklog start time.** The original design's time engine counted seconds as an integer and
lost `InitialStartTime`, the data `PostWorklog` needs to date the entry. Worklogs would have
gone out with the wrong time. Each row now wraps a real `WatchTimer`, and the on-screen
timer only refreshes.

**Settings restoration on update.** When switching major versions, .NET saves `user.config`
in a new folder and the app copies the previous one. It picked the folder with the
**highest version number**, not the most recently used one: on a machine with several
builds installed, it could restore a configuration abandoned months ago. It now sorts by
last-used date.

**Green connection indicator.** It used to use the brand's red, which reads as an error.
Red is now reserved for the primary action and the running timer.

**Starting with the mouse in Grid view.** A stopped cell doesn't show a start button by
design — the *Pause* button only appears once it's running. The numbered chip is now
clickable, which was the design's intent.

**Text clipping.** Issue keys and titles are now clipped with an ellipsis in narrow
windows, instead of being cut off mid-character.

**Version in the title.** It used to show only *major.minor* (`4.0`). Since
`AssemblyVersion` stays fixed within each major version, the patch is the only visible
number that distinguishes one build from another, so it now shows in full (`4.0.1`).

## Update notes

- v3 configuration **is preserved**: persisted rows, credentials, and preferences are
  copied to the new version's folder on first launch.
- Anyone who was using the v3 grid opens directly into the Ledger view.
- On a fresh install, the default view is now **Ledger** instead of the classic window.
