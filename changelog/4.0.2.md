# Time.Tracking.Jira 4.0.2

Settings, About, and the worklog dialog move to WPF with the handoff design. This
completes the redesign of every dialog opened by the four new views: only the classic
window (`MainForm`) still uses its original WinForms dialogs.

Scope: 20 files — 10 new.

---

## New dialogs

### Settings and About

Same fields and the same behavior as the WinForms version, with the handoff design:
sections separated by 2px rules, checkboxes turned into square **switches** (no rounded
corners, consistent with the rest of the theme), and a full version number (`4.0.2`, not
`4.0`) in the *About* title.

Also in *About*:

- Copyright updated to **2026 Seabury Solutions**.
- Contact updated to **fnas@seaburysolutions.com**.
- The *Visit product homepage* link is removed.

### Log to Jira

Same new-design header — which issue it's posting to and the time, before asking anything
else — with two fixes over the previous integration:

- **The start time edited in the dialog is now actually used.** It used to be ignored,
  and the entry was always logged with the timer's real time.
- **"Save for later" now does something.** It parks the comment with a timestamp and
  restores it the next time that row is opened, just like in v3. It's kept in memory —
  it doesn't survive an application restart.

## Log all in every view

Bulk logging, previously exclusive to the Grid view, is now in all four. It walks through
rows that have both time and an issue, one at a time, in a modal dialog each time.

## Quick view switching

Four icons in the footer of every view — one per layout, drawn to read like a miniature of
the layout itself — let you jump between Ledger, Cards, Focus, and Grid without going
through Settings. The icon for the active view is highlighted. Switching this way also
updates the startup view, just like the combo box in Settings.

---

## Fixes

**Cards minimum width.** With "Log all" added to its header, the day's total got clipped.
The minimum was raised from 560 to 640, re-measured the same way as before.

**A bug in the handoff design itself.** `Forms.xaml` carried a WPF pattern
(`Setter Property="Resources"` on a `DatePicker`) that compiles but fails at runtime, and
took the application down when opening the worklog dialog. Fixed with an implicit style
for `DatePickerTextBox`.
