# Time.Tracking.Jira 4.1.1

Rows can now be **pinned** so they always stay at the top, and each issue can now be
**opened in Jira** — a feature v3 had that v4 hadn't brought back yet. In addition, the
last two windows that still belonged to v3 move to the v4 design: the **Edit time** dialog
and the **floating widget**, which is rebuilt entirely and renamed to **mini window**.
With this, no WinForms form is left in the interface.

Scope: 34 files — 9 new, 8 removed.

---

## Pinning rows

Every row now has a pin-shaped button. Pinning it moves it to the top of the list and
keeps it there.

- **Works across all four views.** All four show the same rows in the same order, so
  pinning one in Ledger also leaves it at the top in Cards, in Grid, and in Focus's queue.
- **The 1–9 shortcuts are renumbered to the new order**: a pinned row becomes row 1.
- Any number of rows can be pinned. Among themselves they keep the order they already
  had, and so do the unpinned ones: pinning a row lifts it, it doesn't reorder the rest.
- **It's saved with the row**, so the order comes back the same after a restart.
- Unpinning a row drops it right below the block of pinned rows, not to the end.

While a row is pinned, the button shows with a **solid ink background and a light-colored
icon** — an "on" state that can't be confused with the 12% tint it had before. In Cards,
where actions are named instead of iconified, the button says **Pin** or **Unpin**. In
Grid, where the action bar disappears while the cell is running, a small pin also appears
next to the cell's number.

The pin icon is drawn open, with straight segments: at 13px a closed tip fills in and
stops reading as a pin.

## The row action bar is reorganized

Secondary actions move into a **dropdown menu** behind a three-dot icon (⋮). What's left
visible is just *Start*, *Log to Jira*, the pin, and *Remove row*:

    [ ▶ Start ]  [ ⬆ ]  │  📌  ⋮  ✕

- **The menu has *Open in Jira*, *Edit issue or subtask*, and *Reset*.**
- It's the same menu in Ledger, in Focus's queue and stage, and in Grid. In Cards, which
  names its actions instead of using icons, the trigger is a **More ▾** text button.
- Where there used to be four 24px icons there are now two plus the menu, so the row gets
  back even more width.

## Open in Jira

Every row can open its issue in the browser from the ⋮ menu (**Open in Jira**). It opens
the **parent task** — not the subtask, which is where the worklog goes but is rarely what
you actually want to look at — with the same URL v3 used to build: base URL +
`browse/` + key. It's disabled if the row doesn't have an issue yet or if no Jira URL is
configured.

## Edit time

Opens the same way as before: double-click on a row's time.

- **It says which row you're working on.** It used to be a loose text box: you had to
  remember which row you came from. Now the header shows the issue's key, its title, and
  the time the row currently holds.
- **The field opens with the value selected**, so you can type right over it, which is
  what you do almost every time.
- **A value that isn't understood gets explained.** The field used to just turn red with
  no further detail; now a message appears with the accepted formats, and focus returns
  to the field. The formats themselves don't change: `2h 15m`, `45m`, `2.25h`, `1d 4h`.
- Enter saves, Escape cancels, same as before.

## Log to Jira: date and time

The worklog dialog had the date picker with Windows' default look — rounded corners,
blue, gradients — which clashed with the rest of the window.

- **New date picker.** Square field with the same border and icon as the other controls,
  and a flat 2px-framed calendar: today's date with an accent outline, the chosen date in
  solid accent.
- **The time field has an `HH:mm` mask.** Digits only, the colon is inserted on its own
  after the hour, and each position is validated as you type (it won't allow `25` or
  `:60`). On leaving the field, a valid value is padded to two digits (`9:5` → `09:05`).
- Validation on submit is stricter: `TimeSpan.TryParse` used to accept `9` as nine days
  and `25:00` as twenty-five hours; now only a real time of day, `HH:mm`, is accepted.

## Mini window

Replaces the floating widget. It's a 380x50 strip with a 2px frame and two lines: the
issue the time is being logged against and, below it, its parent task as context.

    ▌ SEA-1187   Review the hours calculation…            1:24:05   ⏸
    ▌ in SEA-1024 — Hours calculation engine

- **Shows parent and subtask.** If the row has no subtask, the second line disappears and
  the strip is left with just one.
- Red bar and pause button while the clock runs; gray and a play button while paused.
- Can be dragged from anywhere on the strip.
- **Double-clicking anywhere goes back to the full window**, which was hidden while the
  strip was up.
- Always stays above every other window, regardless of the "Always on top" setting: it has
  no taskbar button, so a strip covered by another window couldn't otherwise be recovered.
- **Remembers where it was left.** The first time, it's placed at the top right. If the
  saved position ended up on a monitor that's no longer connected, it goes back to that
  corner instead of opening off-screen.
- **The system tray icon appears while the strip is up.** The strip has no taskbar button
  and the main window is hidden: without that icon, a strip covered by something else
  would leave the application out of reach. A click on the tray icon closes the strip and
  brings the window back.

### What the strip no longer does

The previous widget had five buttons and let you edit the time by typing inside it. The
strip only pauses and resumes. **Resetting the timer, logging to Jira, removing the row,
and editing the time now happen in the main window**, which you get back to with a
double-click.

## Fixes

**Logging to Jira now pauses the timer.** After posting the worklog, the row went back to
zero but, if the timer had been running, it kept running: a new session started with no
posting involved, without it being explicit that it was a different session. Now, if the
post succeeds, that row's timer is left paused — resuming it is a separate click, not a
side effect of logging.

**Searching by number in the Ledger combo boxes works again.** When editing a cell with a
double-click, digits from the top row of the keyboard weren't reaching the combo box: the
1–9 shortcuts that start row N were intercepting them. Typing an issue key was impossible
without resorting to the numeric keypad. Those shortcuts are now **disabled in the Ledger
view** — the only one with inline grid editing — and still work in Cards, Focus, and Grid.

**Enter moves from the issue combo box to the subtask one.** When editing a cell inline,
Enter in the issue combo box now jumps to the subtask one — the same step Tab already did,
which is kept — and Enter in the subtask one closes the edit. Enter used to not move focus
reliably: if a row was highlighted in the dropdown list, the key was consumed there and
never reached the navigation logic.

**The worklog is now dated from the start of the current count.** When logging to Jira,
the dialog's "Start time" sometimes picked up the date from a previous session. Now, when
a log entry resets the timer to zero, the counter restarts completely: the next start
counts as a new session, and its worklog is dated from that moment, not from the start of
the session that was already logged. A count started yesterday and logged today is still
dated yesterday.

## Technical note

- Pinning is applied by moving the row within the single collection all four views render,
  instead of each view sorting on its own: this is why the order, the 1–9 numbers, and
  what's saved to disk can't get out of sync with each other. `settings.json` gains a
  `Pinned` field per row, absent — and therefore `false` — in earlier files.
- `EditTimeForm` and `FocusWidgetForm`, the application's last WinForms forms, are removed,
  along with `ModernIcons` (which drew the widget's icons with GDI+) and `WpfWin32Window`
  (which existed to open `EditTimeForm` modally over a WPF window). WinForms is still
  referenced, but now only for the system tray icon and the file picker in the settings
  window.
- **The main window is only hidden once the strip has rendered its first frame**
  (`ContentRendered`), not immediately after showing it. Hiding it earlier left, in the
  installed application, the strip unpainted: only the rectangle that redrew as the clock
  advanced showed up, over a transparent window. As a side effect, if the strip never
  manages to render, the main window is no longer hidden, instead of leaving the
  application unreachable.
- The strip is bound to the row that was running when it was opened, not to "the running
  row": pausing from the strip leaves nothing running, and a strip bound to that would
  have gone blank.
- `settings.json` gains two settings, `MiniLeft` and `MiniTop`, with the strip's position.
  They're written when the application closes, together with the rest of the
  configuration.
- The view model's `Ticked` event is gone: it existed to redraw the WinForms widget every
  second, and the strip now updates on its own through data binding.
- The 1–9 shortcuts stop being window `KeyBinding`s and move to `Window_KeyDown`. A
  `KeyBinding` to a regular `ICommand` marks the key as handled as soon as its gesture
  matches — whether or not the command actually runs — so it was eating the digit before
  it reached the Ledger's inline editor. The code-behind handler doesn't touch the key
  when the view is Ledger; elsewhere it starts row N as before.
- The ⋮ menu is a `MenuButton` (a `Button` that opens its own `ContextMenu` on a left
  click) plus a new `ContextMenu`/`MenuItem` style in `Controls.xaml` — the app had no
  menu at all until now. `TimeEntryViewModel` gains `OpenInJiraCommand`; the rest of the
  logic already lived in `LedgerViewModel`. `settings.json` doesn't change.
- The active pin uses a new token, `ToggleOnBrush` (solid ink). On Focus's dark stage
  background, it's inverted to a light background with the glyph in ink.
- The `DatePicker` and its `Calendar` get their own `ControlTemplate` and styles in
  `Forms.xaml` (`ModernDatePicker`, `ModernCalendar`, `ModernCalendarDayButton`,
  `ModernCalendarButton`). The time mask is an attached behavior, `inf:TimeMask.Enabled`,
  which works on the digits and derives the colon. An STA test opens the dialog and its
  calendar off-screen to check the template applies without breaking.
