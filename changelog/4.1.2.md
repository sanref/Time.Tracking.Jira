# Time.Tracking.Jira 4.1.2

Times **now save themselves every minute** while the application is open, and also **right
before an unexpected error closes it**. Until now they only saved when the application
closed normally: a crash took with it everything measured since the last normal close.
Also, **removing an empty row no longer asks for confirmation**, and, in Ledger, **each
task's full title now shows on hover**.

Scope: 6 files — 1 new.

---

## Fixed

**An unexpected shutdown no longer takes the times with it.** Rows and their timers were
only written to `settings.json` when the main window closed. If the application ended any
other way — an uncontrolled error like the one reported when opening *Log to Jira*, Task
Manager, a power outage — everything measured since the last normal close was lost. Now:

- **It saves itself every minute**, silently, with no prompts. Worst case, the last minute
  is lost.
- **On an uncontrolled error it saves before closing**, and before the error dialog
  appears, so in that case nothing is lost.
- A running timer is saved with the time it has accumulated up to that point. On reopening
  the application it's restored according to the *Save timer states on program exit*
  setting, same as after a normal close.
- If the automatic save fails (disk full, file locked), nothing is shown: it goes into the
  log and is retried the following minute. Saving on close still warns as before.

Along the way, changes made in **Settings** now also reach disk in under a minute; they
used to wait, like the times, for the application to close.

## Removing an empty row no longer asks for confirmation

A row with **no issue and no time** — the one left over after adding one inline and not
using it — is now removed directly, without the *Are you sure you want to delete this
row?* dialog. There's nothing in it to lose: it's the same criterion by which those rows
were already discarded on save.

- Applies to all four views: the remove-row button is the same in all of them.
- A row with an issue, even if its timer is at zero, or with time, even without an issue,
  still asks as before.

## Ledger: full title on hover

The *Parent issue* and *Subtask* columns in Ledger clip the title with an ellipsis when it
doesn't fit. Now, hovering over either cell shows a tooltip with the key and **the full
title**, wrapped across multiple lines if needed. Below it, the cell's existing hint still
shows (*Double-click to change the issue* / *subtask*).

- If Jira hasn't returned the title yet, the tooltip shows only the key.
- A cell with no issue shows only the hint, same as before.
- While the row is being edited, the combo box still shows its own search hint.

## Technical note

- `LedgerViewModel` gains a second `DispatcherTimer`, at `Background` priority, that
  writes the rows every 60s using the same code as the save-on-close path. It starts only
  after the saved rows have loaded: before that the list is empty, and saving it would
  overwrite the file that holds them.
- The save-on-error path hangs off `Dispatcher.UnhandledException` and doesn't mark the
  exception as handled: the application still closes the same way as before, with the same
  warning. It covers errors on the UI thread, which is where the reported one occurred.
- **The unhandled-error log now includes the full exception**, with its inner exceptions.
  It used to store only the outer message and stack trace, and when what fails is building
  a window, that reduces to *"Set property ... threw an exception"*, with no cause.
- `TimeEntryViewModel` gains `IsEmpty` (no issue and no time). It's used by both deletion
  and saving, which previously had the same condition written by hand in each place: a row
  that isn't saved is exactly one that gets removed without asking.

## Still to verify

- **The cause of the error when opening *Log to Jira* is still unidentified.** The
  client's log shows that building the dialog failed while applying the time mask
  (`TimeMask.Enabled`), but not the inner exception that explains it. On the development
  machine the dialog opens without issue (covered by `WorklogWindowRenderTest`). The log
  this version generates is needed if the error happens again.
- Periodic saving and save-on-error were checked by building and with the test suite, not
  by triggering a real crash with timers running. Still need to: start a timer, wait over
  a minute, kill the process from Task Manager, and confirm the row comes back with its
  time on reopening.
- Removing an empty row without confirmation was checked by building, not click by click:
  still need to add a row inline in Ledger and remove it, and confirm that a row with an
  issue or with time still asks.
- Ledger's tooltips were checked by rendering the view off-screen and opening them by
  code, not with the mouse: still need to see them for real, with a long title, and
  confirm they're legible against Windows' tooltip background.
