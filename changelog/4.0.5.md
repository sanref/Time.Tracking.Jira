# Time.Tracking.Jira 4.0.5

Reliability fixes around logging time to Jira and the application's own logging, plus
cleanup of unused code. No interface changes.

Scope: 18 files — 5 removed.

---

## Fixed

- **"Open log folder" (Settings) could close the application.** The button never actually
  opened anything: since the log had no path assigned (see next point), the attempt to
  read it failed with an uncaught exception. Now, if there's no log path, the button
  simply does nothing.
- **The application log was never written**, whether "Logging" was enabled in Settings or
  not. The logger's file path was never assigned at startup; it's now assigned once at
  startup, together with the saved "Logging" state.
- **Every Jira query overwrote the clipboard** with the full JSON of the response, and
  that same JSON was dumped whole into the log. The log now stores only the status code
  and a short excerpt of the response, and the clipboard is left untouched.
- **Editing a row could silently clear its subtask.** If the subtask no longer appeared in
  the list Jira returns when reopening the dialog — for example, because it was closed —
  the field emptied itself and that association was lost on save. Now, if the original
  subtask isn't in the new list, it stays selectable regardless.
- **Resetting the timer right after logging time could lose the new session.** If the
  timer was reset and a row started again while the previous time submission was still on
  its way to Jira, that submission's confirmation could arrive later and wipe out the
  time that had just started. Now, if that happens, a late-arriving submission doesn't
  touch a session that isn't its own.
- **The error dialog shown after an unexpected failure** pointed to a support contact that
  is no longer current; it now shows the current email address. Also, in a very rare case
  (an internal error that wasn't a .NET exception), that same dialog could fail while
  trying to display itself.

## Technical note: unused code cleanup

- The update check (`UpdateCheck/ReleaseHelper`) is removed: it pointed at the original
  GitHub repository (`carstengehling/jirastopwatch`), not this fork, and nothing called
  it — there was no active update check to lose.
- The part of `JiraClient` left unused since the WPF rewrite is removed: favorite filters,
  an issue's time tracking, comments, and status transitions, along with their DTOs and
  the tests that covered them.
- The persistence of `Settings.PersistedIssues` is removed — a value that kept being read
  and re-saved every session without anything using it since v4 switched to
  `GridPersistedRows`. This doesn't affect the import from the original app (v4.0.3): it
  uses its own copy of that data, independent of this change.

## Still to verify

None of this release's changes were tested against a real Jira instance: logging a
worklog within the timer's race window, subtask preservation on edit, or the logging
itself.
